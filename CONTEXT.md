# Workflow Engine

A minimal durable workflow engine on NATS JetStream: workflows are Go code, runs survive crashes, humans approve or feed steps mid-flight.

## Language

**Workflow**:
A named, ordered list of Steps defined in Go code. Code, not config.

**Step**:
One unit of a Workflow, executed at most once per delivery with a bounded retry budget.

**Run**:
One durable execution of a Workflow, identified by ID, always in exactly one status: scheduled, running, parked, done, failed, or cancelled.
_Avoid_: instance, execution, job

**Scheduled Run**:
A Run that exists with its initial State and a future start time, but has not started. It starts no earlier than that time and as soon as workers are available afterward, including after downtime.

**Reschedule**:
Changing the start time of a scheduled Run before execution begins.

**Cancel**:
Preventing a scheduled Run from starting, moving it to cancelled status. Cancellation is available only before execution begins.

**Park**:
Suspending a Run with no message in flight; it moves again only via Resume. A Step parks by returning ErrPark when its input is missing, and consumes that input when it proceeds.
_Avoid_: pause, block, suspend

**Resume**:
Continuing a parked Run with supplied input, whether from a human or an external system.
_Avoid_: approve (approval is one reason to park, not the operation)

**Hook**:
A durable, addressable input owned by a Run that accepts one event. Later waits use separate Hooks.

**Webhook**:
A Hook that services outside the application call over HTTP at an engine-generated address. Each call is authenticated by the application before it is stored, and calls the Step does not wait for are declined while the Webhook keeps waiting.
_Avoid_: callback URL, endpoint

**Trigger**:
A stable token, chosen by the application and bound to a Workflow, that starts a new Run for every verified call from an outside service. A repeated delivery is a duplicate and starts nothing. Its token is reserved in the Hook token space and never reassigned.
_Avoid_: reusable hook, multi-event webhook

**Retry**:
Re-running a failed Run from the Step that failed, with a fresh retry budget.
_Avoid_: restart (a Retry never rewinds earlier Steps)

**Terminal error**:
A Step error that retrying cannot fix (bad input, human rejection); it fails the Run immediately.

**State**:
The Workflow's own typed data carried by a Run, opaque to the engine.

**Patch**:
A partial change to a Run's State supplied through legacy Resume. Hook-based Resume accepts Hook input instead.

**Hook input**:
The one accepted event for a Hook. It remains available when the receiving Step is retried; a new decision requires a new Hook.

**Hook token**:
The engine-wide unique address used to submit input to a Hook, either generated by the engine or chosen by the caller. It is never reassigned to another Hook.

**Hook name**:
A stable name identifying a particular Hook within its Run. Repeated registration of the same name refers to the same Hook; a distinct wait needs a distinct name.

**Submission**:
An attempt to supply Hook input with a required idempotency ID. Repeating the same Submission with equivalent validated JSON returns its original receipt; whitespace and object field order do not distinguish payloads.

**JetStream-native**:
The project's design principle: lean on what NATS JetStream provides (redelivery, backoff schedules, dedup, KV revisions, watches) rather than hand-rolled equivalents; hand-rolled logic is reserved for what JetStream cannot know (application-level crash recovery).
